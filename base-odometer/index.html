Base Odometer

One count, written in as many bases as you like. Every row below follows the same rule as the printed binary counter: flip the first position, and the carry ripples left.

The rollover rule. When a position goes past its largest digit, it resets to 0 and bumps the position on its left by one. Only the largest digit changes from base to base, so in every base, “10” means the base itself.

Why 8 bits per channel

  • One channel is one byte. 8 bits give 28 = 256 levels, numbered 0 to 255. That is the same byte the counter above rolls through.
  • One byte is two hex digits. 16 × 16 = 256, so FF is 255 and each channel fits in exactly two digits. Six digits hold all three channels.
  • Three channels make 24 bits. 256 × 256 × 256 = 16,777,216 colors.
  • Why stop at 8? Computers store data in bytes, and 256 steps is fine enough that neighboring shades are hard to tell apart. Smooth gradients can still show bands, which is why HDR video uses 10 bits (1,024 levels) per channel.
  • Light adds up. All three at 255 is white, all three at 0 is black. Red plus green light makes yellow.
  • Naming trap. “24-bit color” and “8 bits per channel” mean the same thing. Old “8-bit color” used one byte for the whole color, so it had only 256 colors total.

Laser check: one bit off

#FF0000 rgb(255, 0, 0) red byte 11111111
#FE0000 rgb(254, 0, 0) red byte 11111110

These differ by one bit and look identical on screen. Laser software that assigns settings by exact color treats #FE0000 as a different color, so that line can be skipped or cut with the wrong power. Some programs snap to the nearest color instead, so check what yours does before trusting a file.

Try this

  1. Set 1, then flip. The binary ones wheel rolls from 1 to 0 and bumps its neighbor, so 01 becomes 10.
  2. Set 15, then flip. Four binary wheels roll at once, and hex goes from 0F to 10 at the same moment.
  3. Turn on Group bits in 4s. Each group of four binary wheels spells exactly one hex digit.
  4. Click the 128 wheel. One click on a high position adds its whole place value.
  5. Set 255, then flip. Binary and hex run out of wheels, so the count overflows to 0. Decimal has room for 256, but a byte does not.
  6. Add base 8. Each octal digit is exactly three bits, so 255 is 377.
  7. Add base 3 or base 36. Base 3 needs six wheels for one byte; base 36 needs two, and its digits run 0 to 9, then A to Z.
  8. Switch Counter size to 16 bits. The same rule carries on: 65,535 + 1 overflows to 0.
  9. Count to any value, then send it to Green. The green channel is that same byte, now controlling light.

Any base works the same way. Base b uses the digits 0 to b − 1, and each place is worth b times the place to its right. Above base 10, the digits continue with letters, so base 36 ends at Z.
